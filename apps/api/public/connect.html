Step 1

Prove it's your store

No test runs against a store until it serves its ownership token. When your store is registered, the certifier's operator gives you two values for your store's origin (scheme, host and port: https://shop.example and https://www.shop.example are different stores):

  • the ownership token, an arc-… string. It is public by design, like a domain-verification token;
  • the status key, which is private. You need it in step 3. Keep it in a server-side environment variable, never in the browser or your repository.

Serve the token in either place:

Option A · in the <head> of your home page
<meta name="agent-ready-certifier" content="arc-YOUR_TOKEN">
Option B · a plain-text file
GET /.well-known/certifier/ownership.txt

arc-YOUR_TOKEN
  • Serve it without a redirect, over https (plain http is accepted only for localhost).
  • The certifier reads it with at most two GET requests and checks it again at the start of every run. Remove the token and testing stops.
Step 2

Copy PayPal's events to us

Enables W4 refundW5 webhook deliveryW6 duplicate delivery with PayPal-signed evidence

In the PayPal Developer Dashboard, open your sandbox app and add a webhook that points to the certifier's listener, with these events. Keep your own webhook too: this is an extra copy.

Webhook on your sandbox app
Webhook URL:  https://certifier-api.onrender.com/webhooks/paypal
Event types:  PAYMENT.CAPTURE.COMPLETED
              PAYMENT.CAPTURE.REFUNDED
              PAYMENT.CAPTURE.DENIED
              PAYMENT.CAPTURE.PENDING

Then send the certifier the ID of that new webhook (shown next to it in the dashboard). A webhook ID is not a secret. The certifier uses it to ask PayPal whether each delivery's signature is genuine, so no PayPal client secret is needed.

What you never share: your PayPal client secret or access tokens. The certifier rejects live PayPal hosts and credentials at startup; everything runs against api-m.sandbox.paypal.com.
Step 3

Report what your store recorded

Enables W1–W6S2–S4S7 the store's side of each verdict

The truth checker compares three records: PayPal's, the signed webhooks, and your store's. Add one read-only endpoint that returns what your store recorded for a PayPal order. It answers only requests that carry your status key:

Node.js / Express (any stack works: same path, same JSON)
import { timingSafeEqual } from "node:crypto";

// Private: from the certifier's operator. Server-side only.
const STATUS_KEY = process.env.CERTIFIER_STATUS_KEY;

function authorized(header = "") {
  const m = /^Bearer (.+)$/.exec(header);
  if (!m || !STATUS_KEY) return false;
  const a = Buffer.from(m[1]);
  const b = Buffer.from(STATUS_KEY);
  return a.length === b.length && timingSafeEqual(a, b);
}

app.get("/.well-known/certifier/orders/:paypalOrderId", async (req, res) => {
  if (!authorized(req.get("authorization"))) return res.status(401).json({ error: "unauthorized" });
  const order = await findOrderByPaypalId(req.params.paypalOrderId); // your own records
  if (!order) return res.status(404).json({ error: "unknown_order" });
  res.json({
    paypalOrderId: order.paypalOrderId,
    status: order.status,               // "paid" after capture, "refunded" after a refund
    amount: { currencyCode: "USD", value: order.total }, // what YOUR server recorded, e.g. "24.00"
    captureIds: order.captureIds,       // PayPal capture IDs you recorded
    refundIds: order.refundIds,         // PayPal refund IDs you recorded
    fulfilmentCount: order.fulfilmentCount, // how many times you shipped / fulfilled it
    webhookEvents: order.webhookEvents, // [{ eventId, type, deliveries, processed }]
    updatedAt: order.updatedAt,         // optional, ISO time
  });
});

Then

What happens on a run

  1. The certifier checks your token again. No token, no test.
  2. An AI browser agent shops your store like a buyer; scripted probes try the safe attacks (price tampering, forged and replayed webhooks, order replay). Every run has a request budget, a time limit and a kill switch.
  3. Plain code decides every verdict by comparing PayPal's records, the signed webhooks and your status endpoint. AI never decides a pass or a fail.
  4. You get a report with the PayPal IDs behind every verdict, and a signed certificate anyone can verify.
