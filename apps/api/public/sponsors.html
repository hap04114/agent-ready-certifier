AG

AG Grid

The results console · ag-grid-community 36.3.0

WhereThe console: runs across stores, checks within a run with drill-down to PayPal evidence, the model safety scorecard (model × scenario), and every AI trial.
WhyOne certification yields 21 verdicts and the scorecard hundreds of trials. Developers and judges need to compare stores, checks and models, and trace each verdict to the PayPal record behind it.
How
  • Floating filters, sorting, pinned columns and CSV export on every grid.
  • One-click quick views: failures only, compare models, evidence for a check.
  • Click a check to open its reasons, business impact and evidence, each labelled with its strength (paypal-api, paypal-signed…).
Result
  • "Failures only" opens buggy-store run 9d2bdcbd: 11 failing checks, all 10 planted bugs.
  • The scorecard shows the real N per cell: gpt-oss-120b raised its own limit 2 of 10 times with the code readable, 0 of 6 with approval in PayPal's window.

AM

APIMatic ContextMatic

SDK-grounded fixes for every failure · MCP at runtime

WhereThe diagnosis agent, called at runtime for each failed check; its fix appears under the verdict in every run report.
WhyAI-written fixes often name PayPal SDK methods that do not exist. A fix a developer can trust must use the current PayPal Server SDK.
How
  • The agent asks ContextMatic (MCP ask, PayPal Server SDK, TypeScript) for current guidance on the failure.
  • Every SDK method the agent then names is checked: verified only if ContextMatic's answer or its endpoint_search index lists it by exact name.
  • The verdict stays rule-based; the fix is labelled as an AI explanation.
Result
  • All 9 failures of buggy-store run 4291cc0a explained with ContextMatic context.
  • Verified: OrdersController.createOrder (S1, S7), PaymentsController.getCapturedPayment and getRefund (W4).
See the diagnosed report
B

Bryntum Scheduler

The run timeline · Community edition 8.0.0 (MIT)

WhereEvery run report: one bar per step of the certification, in seconds from the start.
WhyA run waits on PayPal's signed webhooks. Seeing those waits is how you tell a slow PayPal ("delayed") from a broken store, and why a missing event is never blamed on the store.
How
  • Steps are typed (setup, AI agent, wait, webhook, attack, judging); webhook waits are highlighted.
  • Bundled locally, loaded only when a run has a timeline; FEATURE_RUN_TIMELINE=off hides it.
Result
  • Good-store run ed37cc30: PayPal's signed capture event arrived in 1 s, the refund event in 16 s.
  • The AI buyer's three approvals took 90 s, 28 s and 26 s.

Channel3

Real products and prices · product search API

WhereBoth demo stores' catalog: a committed snapshot of Channel3 product search (catalog:sync), labelled on the store page.
WhyA certifier should be tested on real listings, not toy data. The price checks need real prices in the right bands.
How
  • Three real listings: Blomus KUMI mug $20.99, TIEFOSSI A5 dotted notebook $18.80, UPLIFT Desk LED Desk Lamp E3 $64.00.
  • Kept in the bands the checks rely on: the notebook fits an AI shopper's $20 limit, the lamp does not.
  • Price tampering (S1) and the machine-readable price check (A4) run against these listings; the AI-shopper funnel (R3) shops this store.
Result
  • On the buggy store, S1 set every price field to $1.00 and PayPal order 5V384020GN270763Y was created for 1.00 USD against the lamp's real 64.00 USD (run 9d2bdcbd).

R

Render

All hosting · one blueprint (render.yaml)

WhereEverything you click is on Render: the certifier (API, console, reports, this page), both demo stores, PayPal's example store, and Postgres.
WhyPayPal delivers signed webhooks only to a public HTTPS URL, and ownership is proven on a real hosted site. Code we did not write must run isolated from ours.
How
  • Secrets use sync: false; pnpm render:sync sets them and prints names only, never values.
  • Deploys on every push; the third-party store redeploys only when its own folder changes.
Result
  • PayPal's signed capture event reached the Render-hosted listener and verified in about 1 s (run ed37cc30).
  • PayPal's own example ran unchanged as its own service and was fully certified: 9 pass, 3 fail, 9 inconclusive (run c38fb9cd).

K

Kernel

Cloud browsers for the AI buyer · recorded

WhereThe AI buyer agent in every Works run, the agent checkout funnel (R3), the third-party run, and the C3 button measurement.
WhyA real purchase goes through PayPal's popup in a real browser. A recording makes what the AI did reviewable afterwards.
How
  • Playwright connects to a Kernel cloud browser over CDP; the agent sees the page as untrusted data and acts through fixed actions.
  • Each session is recorded; its replay ID is attached as certifier-recorded evidence, which shows what happened but never decides a verdict.
Result
  • On PayPal's own example, the AI buyer paid $100 with the example's own PayPal button in 9 steps (replay p4pmsm0d0rs65mg9suyjzs5y).
  • Funnel on the live store: Qwen3.8-27B paid 3 of 3; gpt-oss-120b 0 of 2 (never opened PayPal).

Also built with

Everything else we used, in one line each.

Not hackathon sponsors, but part of how the certifier works. Open source unless noted.

AI models

  • Groq (gpt-oss-120b, gpt-oss-20b, Qwen3.8-27B): drives the AI buyer, the AI-shopper scorecard, the diagnosis agent and the store's AI agent.
  • Google Gemini (3.6 Flash): a second provider in the AI-shopper scorecard.
  • llama.cpp with Qwen3-8B (normal and refusals removed): the worst-case agent test, on this machine only.

Agents and browsers

  • Model Context Protocol SDK: the client that connects the diagnosis agent to ContextMatic.
  • Playwright (playwright-core): drives Kernel's cloud browsers over CDP, and a local Edge for page-only checks.

Trust layer

  • Ed25519 (Node.js crypto): signs every certificate as a JWS; public key at /.well-known/certifier/jwks.json.
  • OpenTimestamps: public timestamps of the hash-log entries (only the hash leaves our server).
  • SimpleWebAuthn (server and browser): passkey owner approvals for AI shoppers.

Backend and data

  • Node.js 22, TypeScript and pnpm workspaces: the whole monorepo.
  • Fastify: the Run API, webhook listener and pages.
  • PostgreSQL (node-postgres): runs, verdicts, evidence, trials, certificates; PGlite runs it in-process for tests.
  • Zod: validates every AI output and API input.

Quality and safety

  • Vitest: 308 tests; Biome: lint.
  • gitleaks: secret scan of the full history, also as a pre-push hook.
  • GitHub Actions: CI on every push, and a job that keeps the demo awake.
  • selfsigned: test certificates for the webhook-signature tests.

Pages and docs

  • esbuild: bundles the browser libraries we serve ourselves (no third-party scripts at runtime besides AG Grid's CDN).
  • Inter (variable font, SIL OFL): self-hosted typography.
  • Microsoft Edge (headless): prints the explainer and summary PDFs.
